# VIS 代理店ポータル

kViewer の置き換えとして作った、代理店向けのマイページ兼 本部向けの管理画面。

## 何ができるか

**代理店（2次代理店＝エリア統括代理店）**
- ダッシュボード … 今月の件数・売上・報酬見込み・枠の空き
- 顧客一覧 … 自分と配下が獲得した顧客。月・担当コードで絞り込める
- 組織と枠 … 配下の組織図と枠の使用状況。枠が足りなければその場で増枠を申請できる
- 売上・報酬 … 配送が完了した受注だけを月次で集計。配下ごとの小計も出る
- お知らせ／資料 … 本部からの連絡と、販促物などのダウンロード

**本部**
- 代理店管理 … 代理店・取次パートナー・スタッフをタブで分けて一覧
- 増枠申請 … 代理店からの増枠申請を承認／却下する

## 構成

```
ブラウザ ──▶ Next.js（Vercel・無料枠）──▶ kintone REST API
                                          App9  代理店マスタ
                                          App10 受注管理
                                          App12 商品マスタ
```

**データベースは持たない。** 受注は Make 経由で kintone に入り、報酬の単価も kintone の
商品マスタから受注レコードに複製されている。ポータル側に複製すると必ず食い違うため、
kintone をそのまま唯一の正とする。結果、DB の契約が不要でランニングコストは 0 円。

| | |
|---|---|
| 追加のランニングコスト | **0 円**（Vercel 無料枠 ＋ 契約済みの kintone） |
| 技術 | Next.js 16 / React 19 / TypeScript / Tailwind v4 |
| 認証 | 代理店コード ＋ パスワード（bcrypt ハッシュを App9 に保存） |

## 動かす

```bash
npm install
cp .env.local.example .env.local   # 中身を埋める
npm run dev
```

`.env.local` の作り方は `.env.local.example` を参照。
本部のパスワードハッシュは `npm run hash -- 'パスワード'` で作る。

## ログインのしくみ

代理店は自分の**代理店コード**（例 `RIM0002`）とパスワードでログインする。

**パスワードは本部が発行する。** 代理店が自分で設定する仕組みにはしていない。
代理店コードは QR の URL・承認メール・上位代理店の組織図に出てくる準公開情報で、
メールアドレスも名刺やサイトに載っていることが多い。この2つが一致すれば設定できる、
という作りにすると、第三者がまだ未設定のアカウントを先に押さえて乗っ取れてしまう。

発行の手順:

1. 本部が「代理店管理」画面の一番下、「ポータルのログイン情報を発行」で代理店を選ぶ
2. 12文字のパスワードが**その画面に1度だけ**表示される
3. 電話など、確実に本人へ届く方法で伝える
4. 代理店はログイン後、「アカウント設定」で自分のパスワードに変更できる（10文字以上）

本部は `.env.local` の `HQ_LOGIN_ID` でログインする。

パスワードは App9 の「ポータルパスワード」フィールドに bcrypt ハッシュで入る。
このフィールドは `scripts/apply-kintone-changes.sh` で作成済み。

### 停止した代理店の締め出し

ログイン中でも、ページを開くたびに App9 の稼働ステータスを引き直している。
本部が「停止・解約」にすれば、その時点から先は開けなくなる。

## 枠のルール

枠は**階層によって意味が変わる**。取り違えると本部と代理店で見える数字がずれる。

### エリア統括代理店（2次代理店）そのものの枠 — 全国60社

総販売代理店（RIM）の配下に入る統括代理店は、エリアごとに上限がある。

| エリア | 上限 |
|---|---|
| 北海道+東北 | 10 |
| 関東 | 15 |
| 中部 | 10 |
| 関西+近畿 | 10 |
| 中国+四国 | 5 |
| 九州+沖縄 | 10 |
| **合計** | **60** |

（2026-06-25 東純汰さん回答で確定）
エリア区分が「本部」の既存5社は、この枠から除外している（2026-07-09の決定）。

### 統括代理店1社あたりの配下枠 — 合計100枠

| 販路種別 | 上限 |
|---|---|
| 販売代理店 | 10 |
| サロン代理店 | 30 |
| 個人販売パートナー | 30 |
| サロン提携パートナー（取次） | 30 |
| **合計** | **100** |

（2026-07-30 会議「10 30 30で取次30、全部で100の枠」）

上限は App9 の各フィールドで代理店ごとに変えられる。未設定なら上の既定値を使う。

### 枠を消費しないもの

- **スタッフ（コード区分 02）** … 代理店ではなく代理店に所属する個人。
  スタッフ登録シナリオ(#15)は販路種別に「販売代理店」を入れるため、
  販路種別だけで判定すると会社の枠を食ってしまう。コード区分で先に外している。
- **停止・解約になった代理店**

## 報酬の出しかた

受注レコード（App10）に、商品マスタから 1 台あたりの報酬額が複製されている。

| 見ている人のランク | 使うフィールド |
|---|---|
| 総販売代理店 | 総販売代理店報酬用 |
| 2次代理店 | _2次代理店報酬用 |
| 取次店 | 取次店報酬用 |

**「販売代理店」ぶんの受け皿フィールドが App10 に無い。** そのため該当ランクでは金額を
出せず、画面には `—` と注記が出る。商品マスタ（App12）には `販売代理店_額` があるので、
App10 に受け皿フィールドを足して LOOKUP のコピー設定に加えれば解消する。

報酬は**配送が完了した受注**で集計する（会議での決定どおり）。

## まだ繋いでいないもの

- **お知らせ／資料** … 保存先の kintone アプリが未作成。`scripts/create-content-apps.sh`
  を実行してから、出力されたアプリ ID を `.env.local` に書く。それまでは画面に
  「準備中」と表示される。
- **資料のダウンロード** … kintone のファイルは認証が要るため、いまはファイル名の表示まで。
  ダウンロードには認証付きの中継が要る。
